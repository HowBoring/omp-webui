# Domain docs

This repository uses a single context.

Before exploring a domain, read root CONTEXT.md if present and relevant
decisions under docs/adr/. If a document is absent, proceed silently;
domain-modeling creates it when a term or decision is actually resolved.

CONTEXT.md is a glossary, not an implementation spec. Use its canonical
terms in code, tests, issues and documentation.

For skills that default to GLOSSARY.md, use this project's CONTEXT.md
instead; maintain one glossary.

Surface conflicts with existing ADRs explicitly before changing direction.
