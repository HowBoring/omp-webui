# #41 stable approval anchor: source evidence

Status: SOURCE ONLY, unaccepted. No production target, key/record provisioning or private admission.
Root selected the policy in ADR0018 before implementation. Historical actual socket/launcher evidence remains scoped
to its original frozen sources and records; it does not prove this new approval path at runtime.

The old compiled whole-approval-record digest created a cycle through final inventoried Native bytes and closure.
Bootstrap now compiles only a stable outside-release anchor pin. Its strict contents hold installation, dedicated
approval verification key, fixed approval location/protected-parent identity, and version/bounds. It rejects release
closure/schema/component/approval-record digest fields. Build final bytes, inventory the full closure, then separately
sign the outside-release approval using a distinct approval signature domain and key. The signed final tuple includes
closure/schema, release directory/global entry/control identities, bridge/helper/control-I/O/validator digests,
dispatcher reply key, endpoint and state/fences. Public UDS nonce/reply wire behavior remains unchanged.

Each selected approval snapshots opened/named inode/device, exact bytes/digest and change metadata. Bounded no-follow
reads compare before/after opened/named identity and repeated bytes; async verification rechecks both anchor and record.
Replacement or changes permanently invalidate that selection. Bootstrap retains initial selection/failure. There is
no live reload, reconnect approval or auto-enrollment. Publication/revocation/upgrade/rollback require explicit operator
action under existing exclusive control, all-process/shared locks, fences and current-data/TUI compatibility checks,
then manual restart/new generation. Worker-realm independence and existing dispatcher gates remain; this loader does
not implement a cross-realm publication lock. An old signed approval bypasses none of the actual tuple/data gates.

The public approved-client seam refuses a changed record before socket admission and remains closed. Tests use fixed
public RFC 8032 fixture material and temporary protected files. Cases cover wrong installation/approval key/domain,
reply/approval key-role confusion, every signed tuple/control/endpoint field tamper, duplicate/extra JSON fields,
absent/replaced/release-local anchor, replaced protected parent, same-inode rewrite, sticky initial failure, record
replacement after open and during pending signature verification. A compile-only generated fixture inventories every
member after building bootstrap with the stable pin, changes schema/approval, and confirms compiled bytes stay identical.
This tiny fixture is not the final product release inventory or platform/provenance evidence.
