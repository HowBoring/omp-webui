# Experiment scope

Source: https://github.com/HowBoring/omp-webui/issues/27 — DSH 导航与能力接缝：自动创建及动作门禁实证.

Use fixed DSH base 38a6a5c965aa99ab525161efb7cc5cf1fe62fced to demonstrate a small public navigation/action policy patch. Startup, refresh, working-directory selection and restoration must not implicitly create native OMP Sessions. Explicit New/Open remain distinct. Menus, title double-click, shortcuts and input paths obey supported capabilities. Preserve real owner permissions; do not fabricate non-owner grants, hide with CSS, or mutate private navigation instances.

Publish an auditable patch/source identity, build and module manifests/digests, public API documentation, positive/negative call traces and browser evidence. Keep the pristine base separate. If it requires a broad private/core Conversation rewrite, report a blocker and return to composition. Only isolated fixtures: no DSH Agent Host, model or real OMP Session, no user config/history, no vendored DSH source/bundle. This is a prerequisite experiment, not product implementation or final integration acceptance.

Distinguish discovery, explicit directory authorization, native-reference registration, Open and New. Selection/restoration/Open never implicitly expands directory authority. Full authentication and persistent-grant implementation remain outside the fixture.

Busy sessions refuse prompt/steer/follow-up queueing while drafts, answers and Stop remain available. Test multiple authorized pages, cancellation, old Connection/UI state, and startup interaction before a worker's native Session identity has been read, without inventing a usable native Session. Demonstrate only public Client infrastructure plus fixture behavior: no claim that fake Remote proves real OMP RPC, Host admission, or a complete Interaction Broker.
